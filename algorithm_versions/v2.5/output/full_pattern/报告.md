## 1. 这项“未完全覆盖”究竟指什么

“原版 `权值→64×64完整复方向图` CNN 代理没有原样保留”指的是**实现形式没有
保留**，不是方向图数学功能消失。

原版和 V2.4 实际上负责两种不同方向的映射：

```text
原版前向 CNN：
阵元最终幅相权值 w ──> 64×64 复远场 E(theta, phi)

V2.4 智能控制器：
目标角+解析初值+校准/状态 ──> 应下发给阵列的复权值 w
```

前者回答“给定这组权值，会得到什么方向图”，是可学习的**方向图预测器/前向
代理**；后者回答“为了形成目标波束，应该输出什么权值”，才是本研究最终需要的
**智能波束成形控制器**。原仓库 `main.py` 的传统优化链并未调用该 CNN；它是独立
训练支线，而不是原控制程序的必经环节。

V2.4 已经用 `steering_iq + field_from_weights_iq` 在训练、旁瓣评价和 held-out
方向图评价中计算复场，只是没有整理出一个与旧版相同 64×64 输出语义、旧幅相输入和
JSON 数据契约的公开入口。因此此前“功能未完全覆盖”的准确表述应为：

> V2.4 保留了完整方向图的解析计算能力，但没有保留旧学习代理的调用外形和可视化
> 数据封装。V2.5 补齐这层兼容接口，不恢复旧大型解码网络。

## 2. 原版功能的逐层对照

### 2.1 原版输入和输出

原版 `cnn_copilot.py` 从历史 JSON 中读取：

- `applied_amp_errors`：名称容易误解，实际保存最终阵元幅度；
- `applied_phase_errors_rad`：最终阵元相位，单位 rad；
- `mag_db_rows`、`phase_rows`：64×64 方向图。

幅相先转成阵元 I/Q，网络输入为 `[B,N,2]`；网络输出为
`[B,2,64,64]`，通道 0/1 分别是复场实部和虚部。矩阵行是 `phi`，列是
`theta`，历史角网格为：

```text
theta: 60° ... 120°，64点
phi:  -30° ...  30°，64点
```

旧模型把复输出再变换为绝对幅度 dB 和 `[0,2π)` 相位。它不是输出阵元权值，也不根据
目标方向主动成形波束。

### 2.2 原版网络结构

```text
[B,N,2] 阵元I/Q
  -> ComplexConv1d 1->64->128->64 + ComplexTanh
  -> 沿阵元维全局平均（得到128个实数特征）
  -> Linear 128->512->4096
  -> reshape为复64通道、8×8特征
  -> 三层ComplexConvTranspose2d，8×8->16×16->32×32->64×64
  -> 复卷积输出头
  -> [B,2,64,64]
```

旧结构有 2,352,770 个参数；MAC 随输入阵元数变化。历史实际 1×4 路径 `N=4`
为 29,552,128 MAC/样本，原 `flops_analysis.py` 的 31,932,928 则是 `N=16`
结构示例，不能误写成历史 1×4 实算。已记录的历史验证结果为：

- 标准化复损失：`0.00282475`；
- 物理复场 NMSE：`-28.592 dB`；
- 平均样本相对 L2：`3.416%`；
- 幅度相关系数：`0.99854`；
- CPU batch=1 中位时间：约 `3.99 ms`。

这些数值说明旧 CNN 学会了历史数据分布上的近似映射，但不是解析精确解。

### 2.3 原版局限

1. 历史训练数据是固定 1×4；阵元坐标、波长和角网格并未作为网络输入。
2. 历史样本波长为 `6.83`，与当前 V2 默认配置 `6.36502` 不同；不能只凭“都是
   1×4”就混用模型或数据。
3. 一维卷积后做全局平均会弱化阵元身份，网络还要靠大 FC/反卷积解码器重新猜测空间图。
4. 位置误差、幅相响应和互耦没有成为明确的模型输入，换阵列或换网格不能保证泛化。
5. 它用 235 万参数近似一个在仿真中已知且线性的阵列因子，训练误差和数据需求本可避免。
6. 旧 `.pth` 没有独立保存全部标准化统计，脱离原数据集后复用存在风险。

旧 CNN 唯一可能优于纯物理公式的场景，是训练标签来自真实阵列且包含物理模型没有描述的
系统失配。但原历史标签本身由已知仿真公式生成，不能据此证明它学到了额外真实效应。

## 3. V2.5 新增逻辑

### 3.1 物理一致完整方向图层

V2.5 对每个方向计算：

```text
u(theta,phi) = [sin(theta)cos(phi), sin(theta)sin(phi), cos(theta)]
E(theta,phi) = S(r+delta_r) diag(g) C w
             = sum_n [(Cw)_n g_n exp(j k (r_n+delta_r_n) dot u)]
```

其中：

- `w` 是 V2.4 控制器输出或外部给定的复阵元权值；
- `C` 是可选复互耦矩阵；
- `g` 是可选逐阵元幅相响应；
- `delta_r` 是可选三维阵元位置误差；
- `S` 是由几何、波长和方向网格确定的导向矩阵。

理想固定阵列时，`S` 只计算一次并缓存；完整方向图层没有训练参数。它输出：

- `field_iq`：`[B,2,phi,theta]` 完整复场；
- `magnitude`：线性幅度；
- `magnitude_db`：与旧版一致的绝对 `20log10` 幅度；
- `magnitude_db_normalized`：每样本峰值归一到 0 dB 的显示量；
- `phase_rad`：`[0,2π)` 相位；
- 明确的 theta/phi 轴。

### 3.2 兼容与组合接口

新增接口覆盖：

- 4×4 理论阵列和 1×4 实际阵列；
- 任意角网格和旧 64×64 网格；
- I/Q 输入和旧幅度/相位输入；
- 理想、位置误差、幅相响应、互耦四类路径；
- 旧 `mag_db_rows`、`phase_rows`、`applied_amp_errors`、
  `applied_phase_errors_rad` JSON 字段；
- 历史 1×4 几何显式入口 `legacy_forward_1x4_config()`；
- V2.4 控制器与完整方向图的一体化包装；
- `render_pattern=False`，允许未来 FPGA 在线链只输出权值而不计算整幅图。

发布契约固定为 FP32（与 V2.4 控制器、缓存字节统计和组合链一致）；FP64 实例只用于
独立参考和误差审计。实现禁止把 FP32 缓存直接升格后冒充 FP64，切换精度必须重新构造
`FullPatternPhysics(dtype=...)`。

V2.5 的组合关系为：

```text
目标角/校准状态 -> V2.4轻量CNN -> 阵元权值
                                      |-> 实际阵列/未来FPGA
                                      `-> V2.5物理层 -> 64×64完整复方向图
```

完整方向图层是观察器和可微损失层，不篡改控制器权值。

## 6. 参数、计算量和延迟

MAC 口径沿用原项目：Conv/Linear 每次乘加计一个 MAC；完整图的一个复乘累加按
4 个实 MAC 统计。理想表只计缓存导向矩阵与权值的场收缩。非理想路径另需 `Cw` 的
`4N²` 实 MAC 和逐阵元 `g` 乘法的 `4N` 实 MAC；仍未计动态相位生成、三角函数、
sqrt/log10/atan2、激活、投影和内存搬运。动态位置误差不能套用理想缓存路径的延迟。

| 链路 | 拓扑 | 可训练参数 | MAC/样本 | FP32导向缓存 |
|---|---|---:|---:|---:|
| 原学习方向图 CNN | 历史1×4，N=4 | 2,352,770 | 29,552,128 | — |
| 原学习方向图 CNN | N=16结构参考，未验证训练质量 | 2,352,770 | 31,932,928 | — |
| V2.5完整图物理层 | 4×4 | 0 | 262,144 | 512 KiB |
| V2.4控制器+V2.5完整图 | 4×4 | 5,538 | 329,248 | 512 KiB |
| V2.5完整图物理层 | 1×4 | 0 | 65,536 | 128 KiB |
| V2.4控制器+V2.5完整图 | 1×4 | 4,962 | 80,800 | 128 KiB |

与原 CNN 比较：

- 仅完整图计算：4×4 按同为 N=16 的结构口径减少 `121.8×`，历史 1×4
  按 N=4 口径减少 `450.9×`；
- 把智能权值控制器也计入：4×4 仍减少 `97.0×`，1×4 减少 `365.7×`；
- 新完整图层本身增加 0 个参数；端到端参数只来自原样保留的 V2.4 控制器。
- 若启用完整 `Cw+g` 非理想收缩，4×4/1×4 观察器分别为 `263,232/65,616`
  实 MAC，连控制器分别为 `330,336/80,880` 实 MAC；动态导向相位另计。

当前机器为 Windows 11、PyTorch 2.12.1 CPU、AMD64、单线程，200 次 batch=1
中位时间：

| 拓扑 | 控制器 | 仅缓存完整图 | 控制器+完整图 |
|---|---:|---:|---:|
| 4×4 | 0.7631 ms | 0.2511 ms | 1.0413 ms |
| 1×4 | 0.7612 ms | 0.2362 ms | 1.0246 ms |

旧 `3.99 ms` 是历史运行记录，不是本轮在同一进程中的对照，因此只能作为量级参考，
不能把延迟比当作严格硬件加速比。MAC 对比和本轮同环境内的 V2.5 延迟可复核。

## 7. 对“是否应把旧 CNN 原样恢复”的判断

不建议恢复。原因不是 CNN 无用，而是任务分工应更清楚：

- 已知几何传播由零参数物理层精确计算；
- CNN 保留在“目标/校准状态→权值修正”位置，学习非理想控制补偿；
- 若真实方向图与校准物理层仍有系统残差，再训练一个小型残差模块
  `E_real = E_physics + delta_E`，且以独立实测集证明收益后才接受。

直接恢复旧 235 万参数解码器会重新引入固定拓扑、固定网格、大数据需求和高计算量，且
无法解释其误差来自几何、幅相、互耦还是数据分布。

## 8. 与后续 FPGA 的关系

该层是否下到 FPGA 应由使用场景决定：

- 在线波束控制只需输出 4 或 16 个复权值时，可令 `render_pattern=False`，完整图留在
  主机做验收/显示，不占 FPGA 实时预算；
- 若 FPGA 必须实时输出完整图，可把固定导向矩阵放 ROM 并做流式复 MAC；
- 4×4 的 512 KiB FP32 缓存可能不适合小器件，应进一步采用 INT16/INT8 导向表、
  URA 可分离结构、分块流式或主机侧计算；1×4 的 128 KiB 更易实现；
- 若位置误差按样本动态变化，不能直接使用固定导向缓存。工程上应把稳定误差并入离线
  校准矩阵，只让低维慢变状态进入控制器。

V2.5 仍属于 FPGA 综合前算法版本，没有生成 HLS、RTL、DPU 模型或 bitstream。

## 9. 限制与后续判据

1. 解析一致不等于实物一致。真实天线的单元方向性、边缘效应、宽带效应、非线性和完整
   互耦若未进入 `g/C`，物理层仍会有模型偏差。
2. 1×4 可以输出二维角网格，但线阵本身对某些二维方向不可唯一分辨；64×64 图的存在
   不会增加物理孔径自由度。
3. 本版恢复的是前向观察功能，不会自动提高 V2.4 的波束质量；控制质量仍采用 V2.4
   已冻结的 oracle 比例、旁瓣和稀疏测点指标评价。
4. 只有当真实校准集显示物理残差稳定、可泛化，并且小型残差模型在独立测试集显著降低
   误差时，才进入 V2.6 候选；否则保持零参数物理观察器。
