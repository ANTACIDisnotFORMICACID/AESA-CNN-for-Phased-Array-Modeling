# 方法、数据和复核说明

## 1. 唯一用于分组对照的优化方法

所有 `clustered/grazing/moderate/wide` 案例都使用同一个H0/O3流程：

1. 输入四个目标方向的真实HFSS嵌入阵元复远场算子；
2. 构造随机恒模相位、目标二次型主特征向量、加权组合特征向量和已有O2候选等共32个起点；
3. 投影为 `|w_n|=1/4`；
4. 使用温度1.2→0.12的soft-min代理；
5. 对16个相位执行320步Adam，学习率0.065；
6. 按真实HFSS四点 `Gmin` 从所有候选中选最好权值。

O3是高预算可行数值参考，不宣称严格证明全局最优。CNN文件加载列表为空，CNN不参与HFSS真值、目标函数或最终选择。

本版不包含任何困难案例额外精修、SLSQP或不同搜索预算结果，避免与统一O3对照混淆。

## 2. 数据集

- validation：240组，每类60组；用于独立验证。
- holdout：600组，每类150组；作为主要对外统计。
- 每组包含4个方向，每个方向包含3维单位向量和 `3×16` 的HFSS复远场响应。

## 3. 原始数据

### `../../../front_hemisphere_20260906/*_front_suite.npz`

`*_front_suite.npz` 是原始HFSS四点输入的唯一现行副本；本证据目录通过相对路径读取，不再保存第二份相同字节：

- `q [N,4,3]`：目标方向；
- `h [N,4,3,16]`：真实HFSS复远场算子；
- `source_indices [N,4]`：原始方向索引；
- `stratum [N]`：四点空间类型。

### `raw/o3_results/`

`*_o3_results.npz` 是从原始实验文件无损抽取的O3/H0字段：

- `weight [N,16]`：恒模复权值；
- `target_gain [N,4]`：四点线性增益；
- `minimum_gain_db [N]`：四点最低增益dB；
- `solo_gain [N,4]`：完整阵列只服务单点时的能力；
- `rho`：最弱目标相对前半球最高峰的比例；
- `solo_utilization`：最弱目标相对其单点独占能力的比例；
- `spectral_solo_upper_bound`：归一化四点能力的谱上界；
- `source_sha256` 记录抽取来源哈希。

### `raw/sdp_upper_bound/`

这里只保留理论上界字段，不包含随机化候选或额外局部精修：

- `o3_minimum`：O3线性最低增益；
- `constant_modulus_sdp_upper`：恒模SDP上界；
- `arbitrary_amplitude_trace_upper`：只固定总功率时的更宽松上界；
- `constant_modulus_gap_db`、`trace_gap_db`：上界与O3差距；
- `rank_99`：解释99% SDP能量所需秩；
- 数值可行性检查字段。

SDP上界不是一组可实现优化权值，只用于回答“同一恒模相位问题还剩多少潜在空间”。

## 4. 可读数据

`tables/o3_*_cases.csv` 每行对应一组四点，包括：四点方向、四个增益、最低增益、单点能力、16个权值的幅度和相位，以及对应SDP上界。

`RESULTS.csv`、`tables/threshold_rates.csv`、`tables/stratum_statistics.csv` 都可由逐案例数据重新计算。

## 5. 完整性和复核

运行：

```powershell
python tools/verify_package.py
```

脚本会检查：

- validation/holdout案例数和四类分组数量；
- 所有O3权值的幅度是否为1/4；
- 从HFSS算子和权值重新计算的四点增益是否与保存结果一致；
- 每个空间分组是否只出现统一的 `H0_O3_32x320_Adam_phase_only` 方法标签；
- CNN是否明确为空；
- SDP是否逐案例高于或等于O3；
- 包内是否不存在精修/SLSQP数据文件。

文件版本由Git提交记录，不再额外维护整包哈希清单。

## 6. HFSS交叉验证及其与广泛测试的关系

广泛测试和HFSS交叉验证回答不同问题，不能混为同一组统计：

- validation/holdout共840组结果用于描述方向组合变化下的总体性能分布；
- SDP上界用于判断同一恒模相位约束内还剩多少理论改进空间；
- HFSS案例189用于核对一组代表性O3相位在原始全波工程后处理中的绝对实现增益；
- HFSS邻域检查用于寻找该代表案例附近是否存在容易发现的改进，不用于估计总体分布。

案例189的O3离线 `Gmin=4.4968977 dB`，在600组holdout中位于第50百分位，在150组moderate案例中约位于第46百分位。选择该案例的依据是接近总体中位数，而不是增益高低。

HFSS交叉验证输入已与 `tables/o3_holdout_cases.csv` 的案例189逐字段核对：四个方向向量、16个相位和四点离线增益的最大差均为0；16个端口功率之和为1 W。

交叉验证使用HFSS 2025 R2、`Setup2 : LastAdaptive`、47 GHz、`Infinite Sphere1`和 `RealizedGainTotal`。16个端口各输入0.0625 W，总功率1 W，仅相位改变。HFSS直接结果为 `[4.4556, 4.4515, 4.3965, 4.4759] dB`，最低值4.3965 dB。离线O3最低值与HFSS最低值相差0.1004 dB，最大逐点差0.3233 dB。

HFSS复数电场按照

\[
G=\frac{|E_\theta|^2+|E_\phi|^2}{60}
\]

重新计算后，与HFSS `RealizedGainTotal` 的最大差为 `1.15e-5 dB`。这项检查验证了API读取、场分量单位和增益归一化。离线完备远场与HFSS直接后处理之间的零点几dB差异仍可能包含角度插值和数据导出/后处理路径差异，本实验没有进一步把这些因素逐项分离。

固定随机种子 `20260906` 的HFSS邻域检查包含1个O3起点和24个候选。扰动标准差为20、10、5、2、1、0.5度，每档4次。最佳最低增益为4.4265 dB，相对HFSS中的O3起点提高0.0300 dB。该检查只能支持“未发现明显局部遗漏”，不能证明全局最优。

原生Optimetrics尝试没有形成有效结果，因为本工程的源相位属于已有场解的后处理激励组合，不能通过当前API路径稳定构成设计变量到远场目标的数据链。该失败记录仅用于说明工具边界，不计入优化性能结果。
